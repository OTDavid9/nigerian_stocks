# South German Credit Dataset
## Description
The South German Credit dataset is a modified version of the German Credit dataset from the Statlog project. It contains information about 1,000 loan applicants and is commonly used for 
credit risk analysis.
## Target Variable
- credit_risk
  - 1: Good credit risk
  - 0: Bad credit risk
## Features
| Column | Description |
|----------|-------------|
| checking_account_status | Status of checking account |
| duration_months | Duration of credit in months |
| credit_history | Previous credit history |
| purpose | Purpose of the loan |
| credit_amount | Amount of credit requested |
| savings_account | Savings account status |
| employment_duration | Length of employment |
| installment_rate | Installment rate as percentage of income |
| personal_status_sex | Personal status and sex |
| other_debtors_guarantors | Other debtors or guarantors |
| residence_duration | Years at current residence |
| property | Property or assets owned |
| age | Age in years |
| other_installment_plans | Other installment plans |
| housing | Housing status |
| existing_credits | Number of existing credits |
| job | Occupation category |
| dependents | Number of dependents |
| telephone | Telephone ownership |
| foreign_worker | Foreign worker status |
| credit_risk | Target variable |
## Source
- UCI Machine Learning Repository
## Number of Records
- 1,000 observations
## Number of Variables
- 20 features
- 1 target variable
"""
with open("README.md", "w") as f:
    f.write(documentation)

import pandas as pd
# Select numerical columns
numerical_features = df.select_dtypes(include=["int64", "float64"]).columns
def detect_outliers_iqr(data):
    outlier_summary = []
    for column in numerical_features:
        Q1 = data[column].quantile(0.25)
        Q3 = data[column].quantile(0.75)
        IQR = Q3 - Q1
        lower_bound = Q1 - 1.5 * IQR
        upper_bound = Q3 + 1.5 * IQR
        outliers = data[
            (data[column] < lower_bound) |
            (data[column] > upper_bound)
        ]
        outlier_summary.append({
            "Feature": column,
            "Number of Outliers": len(outliers),
            "Lower Bound": round(lower_bound, 2),
            "Upper Bound": round(upper_bound, 2)
        })
    return pd.DataFrame(outlier_summary)

Note of Outlier Dectection, Resolution and Justification
  I first identified the outliers by applying the IQR method and visualizing them using boxplot. Instead of applying single method to all the numerical features, I decided to deal with the outliers in each feature by feature. This
approach helped in retaining meaningful information while reducing the effect of extremely high values which could negatively impact the performance of the models.
1. Duration (Months): We first detected 70 outliers, and since it is a continuous numerical variable, high values of loan duration would skew the ML model ,we used winsorisation by applying IQR based capping on the
duration to restrict the range of large values. There were no outliers after pre-processing.
2. Credit Amount: We detected 72 outliers which is evident by the right skewness of credit amounts. We decided to apply log transformation (log1p) on the feature in order to reduce the skewness of the distribution by
shrinking the large values to prevent them from affecting the model without changing their ranking. After log transformation we observed that the number of outliers reduced to 1 which we decided to keep as it represents
a high amount credit rather than an error.
3. Installment Rate: There were no outliers in this feature and thus we didn’t perform any pre-processing.
4. Residence Since: There were no outliers after the application of IQR method, so no pre-processing was done.
5. Age: We found 23 outliers in age. As age is a continuous variable, we usedwinsorisationby applying IQR capping on age. After preprocessing there were no outliers.
6. Existing Credits: We detected six observations as outliers according to the IQR method. However, existing credits represents a discretecount with a small set of possible values. These were not abnormal and were
legitimate observations, so we decided not to perform any pre-processing.
7. Dependents: According to the IQR method we had found 155 outliers for dependents. This can be seen as a weakness of IQR method. Dependents has only two valid values (1, 2). Since majority of clients have 1
dependent , the upper bound calculated using the IQR method becomes equal to 1, hence all observation with value 2 become outliers which are not actual outliers but just the another valid value. So we decided not to
perform any pre-processing on the data.

import numpy as np
from sklearn.metrics import (
    accuracy_score,
    precision_score,
    recall_score,
    f1_score
)
class LogisticRegressionFromScratch:
    """
    Logistic Regression implemented from scratch using Gradient Descent.
    """
    def __init__(
        self,
        learning_rate=0.01,
        iterations=1000,
        tolerance=1e-6,
        patience=50
    ):
        self.lr = learning_rate
        self.iterations = iterations
        self.tolerance = tolerance
        self.patience = patience
        self.weights = None
        self.bias = None
        self.cost_history = []
    # -------------------------------------------------
    # Sigmoid Function
    # -------------------------------------------------
    def _sigmoid(self, z):
        z = np.clip(z, -500, 500)
        return 1 / (1 + np.exp(-z))
    # -------------------------------------------------
    # Binary Cross Entropy Loss
    # -------------------------------------------------
    def _compute_cost(self, y, y_pred):
        m = len(y)
        epsilon = 1e-15
        y_pred = np.clip(y_pred, epsilon, 1-epsilon)
        cost = -(1/m) * np.sum(
            y*np.log(y_pred) +
            (1-y)*np.log(1-y_pred)

Model Comparison
The three machine learning models were evaluated on the test set using the following performance metrics:
- Accuracy
- Precision
- Recall
- F1-Score
- ROC-AUC
Each metric provides a different perspective on model performance. Since the German Credit dataset is moderately imbalanced, relying solely on accuracy can be misleading. Therefore, F1-Score and ROC-AUC were also
considered because they account for the trade-off between true positives, true negatives, false positives, and false negatives. This is particularly important in credit risk prediction, where misclassifying a high-risk applicant as
low-risk can have significant financial consequences.
---
1. Logistic Regression
Logistic Regression achieved solid predictive performance while remaining the most interpretable model among the three classifiers.
Advantages
- Easy to understand and explain.
- Model coefficients indicate how each feature affects the probability of a customer being classified as a bad credit risk.
- Suitable for financial institutions where explainability is essential for regulatory compliance and decision-making.
Limitations
- Assumes a linear relationship between the features and the log-odds of the target.
- May struggle to capture complex nonlinear relationships in the data.

Discussion
Because the German Credit dataset contains a higher proportion of good credit applicants, accuracy alone is not an appropriate evaluation metric.
For example, if approximately 70% of customers have good credit, a model that simply predicts "Good Credit" for every applicant would achieve around 70% accuracy, despite having no ability to identify risky applicants.
For this reason, greater emphasis should be placed on metrics such as:
- Precision, which measures how many predicted bad-credit applicants are actually bad.
- Recall, which measures how many actual bad-credit applicants are correctly identified.
- F1-Score, which balances precision and recall.
- ROC-AUC, which evaluates the model's ability to distinguish between good and bad credit applicants across different classification thresholds.
These metrics provide a more comprehensive assessment of classifier performance in imbalanced datasets and are especially valuable in financial risk prediction, where the cost of misclassification is asymmetric.
